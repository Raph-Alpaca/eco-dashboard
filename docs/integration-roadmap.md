# 대시보드를 실제 홈페이지(keep.go.kr)에 연결하는 단계별 안내

> 이 문서는 기술 담당자가 아닌 분도 읽을 수 있게 썼습니다. "무엇을, 누가, 어떤 순서로" 결정하면 되는지에 초점을 둡니다.

## 0. 먼저 알아둘 세 겹 구조

대시보드가 홈페이지 안에서 동작하려면 세 가지가 맞물려야 합니다.

```
 ┌───────────────────────┐      ┌───────────────────────┐      ┌───────────────────────┐
 │  ① 화면(대시보드)      │ ◀──  │  ② 데이터(집계 큐브)    │ ◀──  │  ③ 원자료(비공개)        │
 │  브라우저에서 그림·표  │      │  문항별 합계만 담은 파일 │      │  응답자·기관 단위 자료   │
 │  를 그리는 코드        │      │  (개인정보 없음)         │      │  기관 내부에만 보관       │
 └───────────────────────┘      └───────────────────────┘      └───────────────────────┘
          ▲
          │ 홈페이지(keep.go.kr)의 메뉴·디자인·로그인 안에 "끼워 넣기"
```

- **①화면**은 지금 만든 그대로 어디에나 올릴 수 있는 정적 파일(HTML/CSS/JS)입니다. 서버 프로그램이 필요 없습니다.
- **②데이터**는 `data/cubes/*.json` 입니다. "셀(학교급×시도×…)별 응답 합계"만 있고 개인·기관을 식별할 정보는 없습니다. 지금은 보고서 공표값에 맞춘 합성 데이터이고, 나중에 실제 데이터로 만든 큐브로 **파일만 바꾸면** 됩니다.
- **③원자료**는 절대 홈페이지로 나가지 않습니다. 큐브는 원자료를 가진 기관 안에서 `tools/build_cubes.py`로 만들어 ②만 내보냅니다.

홈페이지에 "끼워 넣는" 방식은 세 가지 중 고르면 됩니다.

| 방식 | 하는 일 | 장점 | 단점 | 적합한 시점 |
|---|---|---|---|---|
| **A. 링크** | 홈페이지 메뉴에서 대시보드 주소로 새 창을 엽니다 | 가장 쉽고 빠름, 홈페이지 수정 거의 없음 | 디자인·로그인이 분리됨 | 1차 공개·시범 운영 |
| **B. 임베드(iframe)** | 홈페이지 페이지 안에 대시보드를 창처럼 넣습니다 | 홈페이지 메뉴 안에서 보임 | 높이 조절·모바일에서 신경 쓸 점이 있음 | 정식 메뉴 편입 |
| **C. 통합** | 홈페이지 코드에 대시보드 화면을 직접 넣습니다 | 디자인·로그인·권한 완전 통합 | 운영사 개발 작업 필요 | 로그인별 상세 보기 등이 필요할 때 |

## 1. 단계표

| 단계 | 무엇을 | 누가 | 산출물 | 걸리는 시간(감) | 박사님이 결정할 것 |
|---|---|---|---|---|---|
| **0. 지금** | GitHub Pages 프로토타입(합성 데이터) | 선생님 | 공개 URL, 저장소 | 완료 | 연구보고서에 어떤 화면을 레퍼런스로 넣을지 |
| **1. 지표·데이터 계약 확정** | 어떤 문항·축을 공개할지, 억제 규칙(예: 30명 미만 비공개), 연 1회 갱신 절차 합의 | 연구진 + 보전원 통계 담당 | `docs/data-spec.md` 확정본, 코드북 | 2~4주 | 공개 범위(시도별까지? 권역까지?), 억제 기준 |
| **2. 실데이터 시범 적용(내부)** | 보전원 PC에서 원자료 CSV → `build_cubes.py --real` 실행 → 큐브 생성 → 내부망에서 화면 검토 | 보전원 담당자(+선생님 원격 지원) | 실데이터 큐브, 검토 의견 | 1~2주 | 수치 검토자 지정 |
| **3. KEEP 1차 연계(링크 또는 임베드)** | 정적 파일을 운영사 서버의 하위 경로(예: `keep.go.kr/dashboard/`) 또는 서브도메인에 올리고, '현황 정보' 또는 '환경교육 정책자료실' 메뉴에서 연결 | KEEP 운영사 + 보전원 정보보안 담당 | 메뉴 연결, 보안성 검토서, 웹접근성 점검 결과 | 4~8주(행정 절차 포함) | 메뉴 위치, 링크/임베드 중 택일, 공개 일정 |
| **4. 데이터 연계 자동화** | 매년 조사 후 (a) 관리자 화면에서 CSV 업로드 → 서버가 큐브 생성, 또는 (b) KOSIS 공표분을 API로 받아 큐브 생성. 화면은 `config.js`의 `dataSource: 'api'`로만 전환 | 운영사 개발 | 업로드/연계 기능, 운영 매뉴얼 | 6~10주 | (a)/(b) 선택, 갱신 책임자 |
| **5. 정식 통합·고도화** | KEEP 디자인·메뉴에 완전 통합, 로그인 권한(공개용/내부 상세), 서버에서 보고서 PDF·HWPX 자동 생성, 연차 비교(시계열) | 운영사 개발 + 연구진 | 통합 화면, 권한 정책, 연차 비교 기능 | 3~6개월 | 내부용 상세 분석 범위, 시계열 기준(문항 변경 관리) |

## 2. 각 단계에서 실제로 일어나는 일

### 1단계 — 지표·데이터 계약
- 대시보드는 "코드북"(문항·보기·척도·축 정의)과 "큐브 규격"으로 움직입니다. 이 둘이 **데이터 계약**입니다. 계약을 확정하면 화면 쪽과 데이터 쪽이 따로 일할 수 있습니다.
- 결정할 항목: 공개 문항 목록, 공개 축(학교급·권역·시도…), 억제 기준(사람 단위 30명 등), 가중치 적용 여부, 연도 표기 방법.
- 결과물: `data/codebook/*.json`(현재 파일을 그대로 쓰되 비공개 문항 삭제), `docs/data-spec.md` 확정.

### 2단계 — 실데이터 시범 적용
1. 원자료를 `data/real/TEMPLATE_*.csv` 양식(열 이름 = 코드북 문항 id)으로 정리합니다.
2. 기관 내부 PC에서 `python tools/build_cubes.py --real --suppress-min 30 --coarsen sido=region5s` 를 실행합니다.
   - `--suppress-min 30`: 30명 미만 셀은 큐브에 아예 담지 않습니다(사전 마스킹).
   - `--coarsen sido=region5s`: 시도 대신 권역으로 거칠게 담습니다(표본이 적은 조사에 권장).
3. 생성된 `data/cubes/*.json`과 화면 파일을 내부망 PC에서 열어 검토합니다(`서버실행.bat`).
4. `python tools/validate.py`로 공표값과 큐브 값이 같은지 자동 비교합니다.

### 3단계 — KEEP 1차 연계
- **운영사 협의**: KEEP은 Java 기반 홈페이지입니다. 정적 파일(대시보드)은 어떤 서버에도 올릴 수 있으므로 운영사에 "정적 파일 폴더를 하위 경로에 배치하고 메뉴에서 링크(또는 iframe)해 달라"고 요청하면 됩니다.
- **보안성 검토**: 서버에서 실행되는 코드가 없고(정적 파일), 개인정보가 없는 집계 파일만 올라가므로 검토 범위가 작습니다. 검토 시 제출할 것: 파일 목록, 외부 자원(ECharts 라이브러리는 저장소에 포함, 폰트는 CDN → 필요 시 내부 배치), 데이터 설명(집계만).
- **웹접근성(KWCAG 2.2)**: 모든 차트에 '표 보기'가 있고 색만으로 의미를 전달하지 않도록 만들었습니다. 인증 심사 시 대체 텍스트·키보드 조작 항목을 보완합니다.
- **개인정보**: 집계 큐브만 공개하므로 영향평가 대상이 아니라는 근거 문서를 함께 둡니다.

### 4단계 — 데이터 연계 자동화
- 방식 (a) **관리자 업로드**: 운영사가 "CSV 업로드 → 서버에서 `build_cubes.py` 실행 → 큐브 교체" 화면을 만듭니다. 파이썬 스크립트는 그대로 서버에서 쓸 수 있습니다.
- 방식 (b) **KOSIS 연계**: 실태조사는 국가승인통계로 국가통계포털에 공표됩니다. KOSIS 공유서비스 API로 공표 표를 받아 큐브로 변환하는 어댑터를 추가합니다(화면 무수정).
- 화면은 `config.js`에서 `dataSource: 'api'`, `apiBase: '/api/dashboard/'`로 바꾸면 같은 경로로 요청합니다.

### 5단계 — 정식 통합
- 로그인한 내부 사용자에게만 더 세밀한 축(예: 시도×학교급)을 보여주려면, 서버가 권한에 따라 다른 큐브를 내려주면 됩니다(화면은 동일).
- 연차 비교는 큐브 파일에 `year` 축을 추가하는 방식으로 확장합니다. 문항이 바뀐 해는 코드북에 "비교 불가" 표시를 둡니다.

## 3. 자주 묻는 질문

- **비용이 많이 드나요?** 3단계(링크/임베드)까지는 운영사의 소규모 작업(파일 배치·메뉴 연결·보안 검토)입니다. 4·5단계부터 개발 비용이 듭니다.
- **원자료가 유출될 위험은?** 원자료는 서버에 올리지 않습니다. 공개되는 건 셀별 합계뿐이고, 소표본 셀은 만들 때부터 비웁니다.
- **누가 운영하나요?** 연 1회 조사 후 큐브를 다시 만들어 교체하는 일이 전부입니다. 4단계가 되면 업로드 화면에서 담당자가 직접 합니다.
- **보고서 양식은 바꿀 수 있나요?** 패널 구성(`js/layouts.js`)과 인쇄 양식(`css/print.css`)을 바꾸면 됩니다. 문항 추가는 코드북에 한 줄 추가로 끝납니다.
